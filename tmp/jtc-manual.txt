1 Introduction
Selamat datang di J&T Cargo! Kami sangat gembira untuk menyambut Anda di sini. Untuk memper-
mudah proses Anda menggunakan Open Platform J&T Cargo, kami menyiapkan dokumen ini untuk
membantu Anda bernavigasi di antara beberapa hal yang mungkin Anda ingin ketahui ketika memulai
dengan J&T Cargo.
Platform OpenAPI kami diharapkan dapat membantu Anda dengan kebutuhan pengiriman-pengiriman
paket besar yang cocok untuk kasus penggunaan seperti e-commmerce, retail, pengiriman rutin,
UKM (Usaha Kecil & Menengah), dan segala sesuatu diantaranya.
OpenAPI J&T Cargo membantu developer untuk mengakses fungsionalitas J&T Cargo. Beberapa
contoh metode API yang dapat digunakan meliputi pembuatan pesanan pengiriman, cek biaya kirim,
cek SLA (Service Level Agreement), dan pelacakan status paket.

3.2 Struktur Request API
Struktur request API Open Platform di lingkungan production dan sandbox memiliki struktur yang
sama, yaitu Header dan Body.
3.2.1 Struktur Header
Header untuk setiap request memiliki struktur yang sama, yaitu apiAccount, digest, dan timestamp.
Key Type Required? Value Description
apiAccount Numeric Y apiAccount of the developer account
digest String Y Header Signature
timestamp Numeric Y Timestamp in UNIX format, in milliseconds
3.2.2 Struktur Body
Body dari request hanya memiliki satu parameter yaitubusiness parameter atau disebut juga bizCon-
tent. Parameter bizContent berisi parameter-parameter lain terkait untuk interface yang digunakan.
Key Type Required? Value Description
bizContent String Y Business Parameter / Body Content

3.3 Digest Generation
Setiap request Open API J&T Cargo memiliki dua jenis signature/digest untuk memastikan bahwa
request yang dikirim adalah asli dan tidak diubah oleh pihak ketiga: Header Signature dan Body
Signature.
3.3.1 Header Signature (Header Digest
Header Signature digunakan untuk verifikasi bahwa konten dari request API yang dikirimkan tidak
dicegat dan diubah tanpa wewenang.
Algoritma untuk menghasilkan Header Digest sebagai berikut:
digest = Base64(MD5(bizContent + privateKey))

8 */

3.3.2 Body Signature (bizContent Digest)
Body Signature digunakan untuk verifikasi identitas pelanggan dan mitigasi kemungkinan kesalahan

cipherText = strToUpper(MD5(plaintext pwd + "jadada236t2"))
digest = Base64(MD5(customercode + cipherText + privateKey))

4 *
5 * @param string $ c u s t o m e r C o d e The unique code i d e n t i f y i n g the cu st om er .
6 * @param string $ p l a i n t e x t P w d The cus to me r ’s p l a i n t e x t pa ss wo rd .

8 * @return string The base64 - encoded body digest .
9 */

11 // Step 1: Ge ner at e the salted MD5 hash of the p l a i n t e x t pa ss wo rd
12 $salt = " j a d a d a 2 3 6 t 2 " ; // Static salt value for pa ss wo rd hashing
13 $ m d 5 P l a i n t e x t = s t r t o u p p e r ( md5 ( $ p l a i n t e x t P w d . $salt ) ) ; // Combine
pa ss wo rd and salt , then hash
14
15 // Step 2: Combine the cu st om er code , hashed password , and private key
16 $ c o m b i n e d S t r i n g = $ c u s t o m e r C o d e . $ m d 5 P l a i n t e x t . $ p r i v a t e K e y ;
17
18 // Step 3: Ge ner at e the MD5 hash of the c om bi ne d string
19 $ m d 5 F i n a l = md5 ( $ c o m b i n e d S t r i n g ) ;
20
21 // Step 4: Convert the MD5 hash ( h e x a d e c i m a l ) to binary and then base64
encode it
22 $digest = b a s e 6 4 _ e n c o d e ( hex2bin ( $ m d 5 F i n a l ) ) ; // Hex to Base64
23
24 // Return the final body digest
25 return $digest ;

4 FAQ
1. Bagaimana cara debugging di sandbox?
Silakan gunakan sandbox endpoint (test url) dan hit interface tersebut sebanyak 3 kali berturut
dan sukses. Apabila sudah berhasil, silakan masuk ke menu Console > Sandbox Management
dan interface terkait akan berstatus coordinated.
2. Saya sudah hit 3 kali/lebih dari 3 kali dan sukses, tapi masih belum berstatus coordinated!
Silakan pastikan untuk sandbox endpoint (test url) yang digunakan memiliki UUID pada url nya.
3. UUID dapat dari mana?
UUID hanya akan muncul jika anda sudah login, dan dapat ditemukan pada halaman dokumen-
tasi interface yang akan digunakan.
4. Apakah satu akun open platform bisa menggunakan banyak kode pelanggan (customer
code)?
Bisa. Cukup mengganti kode pelanggan pada parameterCUSTOMER CODE dan generate DIGEST
menggunakan password pelanggan (plaintext pwd) terkait ke kode pelanggan yang digunakan.
5. Kenapa resi yang dibuat jumlah kolinya XX padahal harusnya YY?
Untuk parameter totalQuantity saat create order adalah jumlah koli, bukan jumlah barang di
dalam koli.
6. Kenapa paket jadi multikoli padahal hanya 1 koli?
Untuk parameter totalQuantity saat create order adalah jumlah koli, bukan jumlah barang di
dalam koli.
