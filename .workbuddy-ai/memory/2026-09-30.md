# Mobile checkout coupon popup — hardening (2026-09-30)

## Reported
"Popup kupon tidak muncul di halaman versi mobile. Pengguna hanya bisa memasukkan
kode kupon secara manual." Screenshot shows the native "Add coupons" row followed
directly by Subtotal — the `.lwc-open-coupon-modal` ("Kupon & promo") row is
absent from the mobile order summary.

## Investigation
Could NOT reproduce a missing picker locally. Verified working at 390 / 459 / 768 /
900 / 1024 / 1200 / 1440 px, guest and with `diskon50` applied, after expanding +
submitting the native coupon panel, and under 20x CPU throttling + slow 3G
(picker appeared once React hydrated, ~20s). Shipped `lovecatz-woocommerce-complement.zip`
does contain the picker code, so it is not a stale-build problem.

## Real failure mode found and reproduced
The picker is injected *after* `.wc-block-components-totals-coupon`. On mobile the
order-summary sidebar (`.wc-block-checkout__sidebar`) carries `order:0` and is
rendered FIRST in the DOM, so its coupon container is the first `.first()` match —
but its body is collapsed, so that container is invisible. If
`renderCheckoutCouponPicker()` runs at a moment when only that container exists,
the picker is injected into a hidden node. The old guard
(`if ($('#lwc-checkout-coupon-picker').length) return;`) then blocked every later
retry, stranding an invisible picker permanently — exactly the reported symptom.

Reproduced deterministically by moving the picker into
`.wc-block-checkout-sidebar .wc-block-components-checkout-order-summary__content`
→ `pickerVisible: false`.

## Fixes
`promo/promo-dashboard.js`
- `getCheckoutCouponContainer()` prefers the first **visible** container, with a
  fallback to the first match, plus `.wc-block-checkout__actions` /
  `.wp-block-woocommerce-checkout-actions-block` as a last-resort home so the
  picker always has a rendered parent.
- `renderCheckoutCouponPicker()` is now self-healing: if the picker exists but is
  not visible AND a visible container exists, it is removed and re-homed. Guard
  added for `typeof lwcPromoDashboard === 'undefined'`.
- `MutationObserver` now re-renders when the picker is missing **or not visible**
  (was: only when missing). The render function bails out when no visible
  container exists, which prevents a re-render loop.
- Retry interval (700ms, up to 25 tries) now stops only once the picker exists
  AND is visible — covers slow-phone hydration.
- Debounced `resize` / `orientationchange` handler, because a viewport change can
  flip WooCommerce's container query without any DOM mutation.

`promo/promo-dashboard.css`
- Mobile-only button affordance for the picker (teal border, light teal fill,
  9px radius, 13px padding) via `@media (max-width: 699px)`. Cosmetic, so a plain
  media query is correct here; only the layout-hiding rule needs a container query.

Version bumped 1.0.90 → 1.0.91.

## Verified (CDP, device emulation)
- Mobile 390px: picker rendered and visible; button styles confirmed
  (`border 1px rgb(15,118,110)`, `background rgb(240,253,250)`, `radius 9px`).
- Self-heal: after stranding the picker in the hidden sidebar it was re-homed
  automatically by the MutationObserver **with no resize event** — parent returned
  to `wp-block-woocommerce-checkout-order-summary-coupon-form`, `pickerVisible: true`.
- Modal works on mobile: bottom sheet `Pilih kupon`, coupon card "diskon50 /
  50% discount · Maximum Rp150.000", selection checkbox, "Add Coupon" button
  (disabled until a coupon is checked).
- Desktop 1440px unaffected: original subtle border `1px rgb(225,229,232)`,
  transparent background, sidebar title still `display: flex`.
