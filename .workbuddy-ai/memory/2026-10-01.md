# 2026-10-01

## Customer history metabox currency (lovecatz-woocommerce-complement)

Customer history card on the WooCommerce order edit screen (`wp-content/plugins/woocommerce/templates/order/customer-history.php`) was rendering every customer's spend with the store's base-currency symbol (`Rp`), even when the buyer paid in USD. The `LWC_Currency_Converter` (`includes/core/class-lwc-currency-converter.php`) now:

1. Adds `get_customer_history_for_currency($order, $currency)` — re-aggregates the customer's paid orders in a single currency (HPOS: direct SQL on `wc_orders` filtered by `currency`; CPT: `wc_get_orders(['currency'=>...])`).
2. Adds `get_current_admin_order()` — reads the order from `$_GET['post']` / `$_GET['id']` / `$_POST['post_ID']` for the current admin edit-order request.
3. Hooks `wc_get_template` (`filter_customer_history_template`) so `order/customer-history.php` resolves to the override in `includes/core/templates/order/customer-history.php` only when `is_admin()` and an order resolves. The override passes the order's currency to `wc_price()` and reuses the original WooCommerce totals as a "lifetime across all currencies" hint when mixed currencies exist.

Smoke tests in `tmp/` confirmed USD order #32 now shows `$259` (and 4 USD orders summed correctly), and IDR order #41 keeps `Rp` formatting (no `$` leak). Both harnesses self-cleaned. Plugin header + `LWC_VERSION` bumped to 1.0.92.

## Custom FedEx shipper address (lovecatz-woocommerce-complement)

New optional feature: ship FedEx orders from an address other than the WooCommerce store address.

- New class `shipping/fedex/class-lwc-fedex-shipper-address.php` (`LWC_FedEx_Shipper_Address`) owns the feature. Toggle `lwc_fedex_shipper_address_enabled` plus nine parts under prefix `lwc_fedex_shipper_address_`: `name, company, phone, address_1, address_2, city, state, postcode, country`. `FIELDS` carries per-part `label`/`required`/`max_length`; required = name, phone, address_1, city, postcode, country. Empty country falls back to the store country.
- `LWC_FedEx_API::build_origin_address()` now delegates to `resolve_origin_address()`, and `build_shipper_contact()` prefers the custom contact. Both fall back to the store values when the toggle is off or the address is incomplete, so checkout is never blocked.
- **Two-tier failure policy (deliberate):** rate quotes silently fall back to the store address; AWB/label creation and pickups are *blocked* with an actionable message via `validate_origin_for_shipment()`, because the whole point of the toggle is that the custom origin must be the one printed on the label.
- Admin UI lives in `includes/admin/class-lwc-admin-settings.php` in its own settings section (`lwc_fedex_shipper_address_section`) with a completeness notice (success/warning). Country renders as a `WC()->countries->get_countries()` dropdown. Each part gets its own `register_setting` closure because WordPress passes only the value to a sanitize callback. All registrations are guarded by `class_exists( 'LWC_FedEx_Shipper_Address' )`.
- `LWC_FedEx_API::get_origin_summary()` (public) powers a new "Shipping from …" line + warning notice in the FedEx order metabox (`class-lwc-fedex-order-admin.php`, CSS `.lwc-fedex-origin-summary` in `fedex-order-admin.css`).
- FedEx payload mapping: `streetLines` (array), `city`, `stateOrProvinceCode`, `postalCode`, `countryCode`; contact `personName` / `phoneNumber` / `companyName`. Values are truncated to the documented limits before sending.
- Registered in the bootstrap right after `class-lwc-fedex-account.php`. Version bumped to 1.0.93.
- Test trap: order #32 already carries an AWB with no `item_ids`, so its metabox always emits an unrelated `notice-warning`. Assert on the custom-address wording, never on the mere presence of `notice-warning`.
