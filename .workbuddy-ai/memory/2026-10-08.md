# 2026-10-08 — lovecatz-woocommerce-complement

## Built: Purchase Order (PO) + partial payment / DP (v1.0.97 → 1.0.98)

WooCommerce has no native PO or partly-paid order. Implemented both, managed from
the WooCommerce Orders screen, with settings on the plugin's Order tab.

**New files** (`payment/`):
- `class-lwc-payment-plan.php` — model. Plan meta `_lwc_payment_plan` (`full|po|dp`),
  ledger `_lwc_payments`, deposit percent/amount, PO number/terms/due date.
  Amount paid, balance due and payment status are **derived from the ledger**, never
  cached. `apply_plan()`, `update_deposit()`, `update_purchase_order()`,
  `add_payment()`, `delete_payment()`, `refresh_paid_state()`,
  `sync_plan_from_payment_method()`, customer + email summaries.
- `class-lwc-gateway-purchase-order.php`, `class-lwc-gateway-partial-payment.php` —
  `WC_Payment_Gateway` subclasses mirroring BACS (`update_status` + empty cart +
  `get_return_url`). `has_fields = false` because the store uses the Checkout Block.
- `class-lwc-payment-plan-admin.php` + `payment-plan-admin.{css,js}` — order-screen
  metabox (badges, figures, PO/DP forms, ledger, record-payment form), three AJAX
  actions returning freshly rendered panel HTML, and the Orders-list Payment column.

**Edited:** `includes/core/class-lwc-core.php` (require + init + `register_payment_gateways`),
`includes/admin/class-lwc-admin-settings.php` (`register_payment_plan_settings()` on
`lwc_order_options` + sanitizers), bootstrap version bump, `PRD.md` (new section,
layout, admin workspace, data model).

**Key decisions**
- Plan lives in **order meta, not a custom order status** — payment state must not
  block the existing `processing` → AWB automation.
- Checkout only applies `pending|on-hold|processing` so stock is always reserved
  (`wc_maybe_reduce_stock_items` is hooked to on-hold/processing/completed).
- Deposit is an expectation, not a receipt; the ledger stays manual (user's choice).
- `get_deposit_amount()` returns 0 for non-DP plans — found by the harness, a PO was
  inheriting the site-wide 50% percentage.

**Verification** — `tmp/test-payment-plan.php` (raw-PHP harness, deleted after):
~130 assertions across boot, plan defaults, PO plan, DP plan, ledger
(add/overpay/zero/negative/already-paid), rollback + `_date_paid`, payment-method
sync, gateway availability (master switch + guest rule), both `process_payment`
paths, admin panel render (no warnings), order-list column, settings registration
+ sanitizer clamps + `sync_gateway_defaults`, customer/email summaries, and the
Order tab rendering. All green. Confirmed no leftover orders/options afterwards.

**Not done / open:** refunds are not modelled in the ledger; a partial shipment still
settles against the whole invoice; no checkout-time PO reference field (Checkout
Block does not render legacy gateway fields).
