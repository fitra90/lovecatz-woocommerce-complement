# 2026-09-22

## Promo percentage caps are now currency-aware (v1.0.82)

Fixed `_lwc_promo_maximum_discount` being applied/displayed as if it were already in the shopper currency.

**Root cause:** the cap was stored once as a base-currency number (coupon 27 `diskon50` = Rp150,000) but compared against a shopper-currency discount in `limit_percentage_discount()`. For a USD cart the comparison `$uncapped_total > $maximum` became `20 > 150000` → false → factor `1.0` → the ceiling silently vanished. The same number was rendered with `wc_price()` in the admin list and the checkout card, so it also displayed as "$150,000".

### Final design: two plain input fields

The first attempt used a per-currency meta map plus rate-derived conversion, a currency list built from the configured exchange rates, and a generated input grid. That was rejected as too broad — reverted to dedicated fields.

- Meta: `_lwc_promo_maximum_discount` (IDR, original key, unchanged) and `_lwc_promo_maximum_discount_usd` (new).
- `LWC_Promo_Discounts::SECONDARY_CURRENCY = 'USD'`; `get_maximum_discount( $coupon, $currency )` picks the USD key for USD and the original key for everything else. No map, no rate lookup, no conversion.
- Admin form: `maximum_discount_idr` and `maximum_discount_usd`, both under the existing `lwc-percent-only` toggle class so they appear **only for percentage** discounts. Free shipping keeps a third field (`maximum_discount`) under a new `lwc-free-shipping-only` class. No new CSS; one line changed in `admin-settings.js` (`.lwc-maximum-only` → `.lwc-free-shipping-only`).
- Save path: `post_amount( $key )` reads a non-negative money value from POST; percentage reads the two per-currency keys, free shipping reads the original key. USD meta is only written for percentage coupons.
- `limit_percentage_discount()` resolves the cap in `active_currency()` and the factor cache key includes the currency (this is the actual bug fix).
- `apply_selected_shipping_discount()` uses the same resolver; for a free-shipping coupon in USD the USD meta is empty → no cap, which matches the original effective behaviour.
- Admin list shows both caps: `50% · Maximum Rp150.000 · USD $9`.

### One secondary bug worth keeping

`wc_price()` emits `&#36;` for USD, and both the admin list (`esc_html`) and the checkout card (`$('<span>').text(...).html()`) escape again → the customer would read `&#36;9`. `LWC_Promo_Discounts::format_money()` runs `html_entity_decode()` before the string reaches either renderer. Same class of bug as the JNE label entities. Kept because it is small and prevents a visible regression.

(An earlier version also had to reject a crafted `usd2` key that collapsed into `USD`; with dedicated fields there is no key to forge, so that guard is gone.)

### Verified — `tmp/promo-currency-cap-check.php`, `tmp/promo-admin-currency-check.php`

40 × Rp10,000 = Rp400,000 at 50%:

| Case | Cap | Discount |
| --- | --- | --- |
| IDR | Rp150,000 | Rp150,000 |
| USD | $9 | $9 (was $20 — uncapped) |
| USD, field left empty | none | $20 |

Form: `maximum_discount_idr=150000` and `maximum_discount_usd=9` render under `lwc-percent-only`; the free-shipping field renders under `lwc-free-shipping-only`; list label `50% · Maximum Rp150.000 · USD $9` survives `esc_html`. 20/20 assertions pass.

Coupon 27 final meta: `_lwc_promo_maximum_discount = 150000`, `_lwc_promo_maximum_discount_usd = 9`. The intermediate `_lwc_promo_maximum_discount_by_currency` map was deleted.

## Follow-up: caps are type-scoped and never assumed (same day)

The two-field version still had the shipping promo type sharing the percentage IDR meta key, so a shipping coupon's cap was inherited rather than entered, and a USD shopper's shipping cap was never captured at all (the resolver read the USD key that only percentage promos ever wrote → always 0 → no cap).

**Fix — one cap pair per promo type, resolved from the discount type:**

| Promo type | Base currency | USD |
| --- | --- | --- |
| percentage | `_lwc_promo_maximum_discount` | `_lwc_promo_maximum_discount_usd` |
| shipping | `_lwc_promo_shipping_maximum_discount` | `_lwc_promo_shipping_maximum_discount_usd` |

- `LWC_Promo_Discounts::maximum_discount_keys( $discount_type )` is the single source of truth for the mapping; `get_maximum_discount()` resolves the key from `$coupon->get_discount_type()`.
- The admin file no longer references any cap meta constant (asserted in the harness) — it always goes through that helper, so the setting is generic per coupon rather than tied to any ID.
- POST fields: `maximum_discount_base` / `maximum_discount_usd` (percentage) and `maximum_discount_shipping_base` / `maximum_discount_shipping_usd` (shipping). Renamed the base fields off `_idr` so the field name does not hardcode a currency the label derives at runtime; the `get_option( 'woocommerce_currency', 'IDR' )` fallback was dropped too.
- Cap persistence was extracted out of `save_coupon()` into `save_maximum_discounts( $coupon_id, $type )`. Reason: `save_coupon()` ends in `redirect_with_notice()` which calls `exit`, so it cannot be driven from a CLI harness — the extraction is what makes the save path testable. It also clears the caps for a promo type that has none (`fixed_cart`), so a stale value cannot be picked up later.
- Nothing is defaulted or converted: an empty field stores an empty cap and resolves to 0.

**Verification** — three harnesses, 44 assertions, all passing:
- `tmp/promo-currency-cap-check.php` — percentage cart (Rp150,000 / $9) plus a temporary free-shipping coupon capped at Rp25,000 / $2, proving the shipping promo applies its own cap in the cart and that neither type's caps leak into the other.
- `tmp/promo-admin-currency-check.php` — each type renders its own field pair with its own values; the other type's fields render empty; wrapper classes pin percentage-only vs free-shipping-only visibility.
- `tmp/promo-save-roundtrip-check.php` — POST → meta wiring for both types, cross-type isolation, empty-field clearing, fixed-cart clearing, and source-level invariants (delegation present, no hardcoded cap meta key in the admin).

Both cart harnesses wrap their fixtures in `START TRANSACTION` / `ROLLBACK`; confirmed afterwards that coupon 27 is unchanged and no `lwc-test-shipping` coupon leaked into `wp_posts`.
