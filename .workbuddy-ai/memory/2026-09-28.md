# 2026-09-28

## J&T Cargo Add Order — root cause of 145003082 and the fix (v1.0.88 → 1.0.89)

Symptom: `addOrder` reached J&T sandbox, HTTP 200, `code` = `145003082`,
"Customer order number cannot be empty or too long".

### Root cause (two parts)
1. **There was no WooCommerce → J&T Cargo order mapping at all.** The only way
   to hit `add_order` was the Sandbox Test console with a hand-typed `{}`
   payload. `LWC_JTC_API::signed_request()` injected only `customerCode` and
   `digest`, so no customer order number was ever sent.
2. **The J&T field is `txlogisticId`, not `customerOrderNo` / `orderNo`.**
   Confirmed from the official manual
   `E:\Downloads\JTC_API_Integration_Manual_251208_121336 (1).pdf`, §3.4.1:
   `txlogisticId String(50) Y "Nomor order pelanggan"`, example `ID12345678`.
   (Extract it with pypdf in the managed venv — the PDF is 20 pages.)

Manual 3.4.1 required set: customerCode(30), digest(30), txlogisticId(50),
expressType(30, `FT`), orderType(30, `1`/`2`), serviceType(30, `01`/`02`),
deliveryType(30, `101`), payType(30, `PP_PM`/`CC_CASH`/`PP_CASH`),
sender{}, receiver{}, goodsType(30, `bm000001..bm000011`),
weight String(12) **min 1 KG / max 9999.99 KG**, totalQuantity Int(4) = jumlah
**koli** bukan jumlah barang, offerFee String(12) IDR, remark(200), items[],
signReceipt Int(4), waybillNo(50). Party fields: name(32) mobile(30)
countryCode(20, `IDN`) prov(32) city(32) area(32) address(150).

### Customer order number rules
Source = custom `_lwc_order_number` if present, else `$order->get_order_number()`,
else `LWC{id}`; sanitised to `[A-Za-z0-9_-]`; `-R{n}` suffix when
`_lwc_shipping_change_count > 0`; stored in `_lwc_jtc_txlogistic_id` and reused
so retries never renumber. Over 50 chars → `head(41) . '-' . md5(full)[0:8]`
(never a blind truncation, so uniqueness survives). Filter
`lwc_jtc_customer_order_number`.

### Verification
`tmp/lwc-jtc-addorder-verify.php` (deleted after the run) — 112 checks, all
passed, inside `START TRANSACTION`/`ROLLBACK` with a `pre_http_request` mock.
Proved: header digest == `base64(md5_raw(body_bizContent + privateKey))`, the
signed string is byte-identical to what was sent, 145003082 is a failure (no
AWB stored), HTTP 200 without a bill code is a failure, HTTP 500 is a transport
error, success stores AWB + sorting code, and the 20 sandbox endpoints /
console / health check / AWB-automation policy are unchanged.

Trap: `add_meta_box()` needs `wp-admin/includes/template.php` in CLI harnesses
and then emits "called incorrectly" notices — harmless.

### Sandbox console: schema-driven dummy payloads (v1.0.89, same day)
- The first "Isi contoh" button only knew `add_order`. Replaced by a real
  registry: new file `shipping/jtc/class-lwc-jtc-payload-schema.php`
  (`LWC_JTC_Payload_Schema`). Console receives the samples map via
  `wp_localize_script` (`lwcShippingSettings.jtc_samples`) and JS in
  `includes/admin/admin-settings.js` switches the button label, payload, and
  enabled state whenever the interface dropdown changes.
- Schema fields declare `string|number|enum|object|array`, `required`, `max`,
  `min`, `enum`, `example`, `fields` (for object), `items` (for array).
- Generator rules: numeric enum first value wins; otherwise `example` if
  numeric, else `max(min, 1)`; string fields with `example` clip to `max`;
  arrays produce exactly one object element (raw field maps get wrapped via
  `wrap_object_items`).
- Seeded from the manual only: `add_order` (3.4.1 — full Create Order table),
  `orders` (3.4.2 — minimal `txlogisticId`, the PDF table is a copy/paste from
  Create Order so it is treated as suspect), `shipment_track` (only `billCode`,
  the actual call site in `lovecatz-woocommerce-complement.php:994`).
- New interfaces are added via the `lwc_jtc_payload_schemas` filter, so no
  core edits are required when J&T publishes a new endpoint or when a
  third-party dev supplies the schema.
- The 17 unseeded interfaces make the button stay disabled with the message
  "Tidak ada schema untuk ...". Inventing schemas for them would have sent
  J&T guessed field names — refused.
