# 2026-10-20

## Promo discounts restricted to registered customers (v1.0.99)

Requirement: the discount feature must only appear for registered users, both
from this plugin and from WooCommerce itself.

- `promo/class-lwc-promo-discounts.php`
  - New `LWC_Promo_Discounts::discounts_require_account()` (static): true only for a
    frontend visitor without a session; skips `is_admin()`, cron and WP-CLI so
    staff and scheduled jobs keep working with coupons.
  - `woocommerce_coupon_is_valid` at priority 5 returns false for guests (covers
    cart AJAX, checkout block and Store API — the filter lives in
    `WC_Discounts::is_coupon_valid()`, WC 11.1.1 line ~1260).
  - `woocommerce_coupon_error` at priority 5 replaces the message with a plain-text
    "registered customers only … log in or create an account" (plain text because
    the Store API JSON escapes markup).
  - `woocommerce_cart_loaded_from_session` at priority 5 calls
    `$cart->remove_coupons()` for guests — coupons restored from a session are
    never re-validated by WooCommerce, so a logged-out shopper would keep a
    discount earned while logged in.
- `promo/class-lwc-promo-dashboard.php` (front-end class only, so wp-admin keeps
  the native coupon field)
  - New filter `woocommerce_coupons_enabled` → false for guests. Cart template,
    classic checkout coupon form, Cart block and Checkout block all gate on it,
    so the native coupon input disappears for guests.
  - `get_checkout_coupon_data()` returns `array()` for guests; the JS picker then
    never renders for them.
  - `is_coupon_available_at_checkout()` guests → false.
  - `has_account_only_checkout_promos()` re-scoped: since every promo now needs an
    account, the guest invitation shows whenever any live (published, unexpired,
    not exhausted) promo exists.
- `promo/promo-dashboard.js`: `renderCheckoutCouponPicker()` delegates to
  `renderGuestInvite()` for guests (invite only, no mode/modal, no coupon codes);
  `applyCouponFromStorage()` clears the stored code for guests.
- `promo/class-lwc-promo-admin.php`: one description line in the promo manager
  stating coupons are registered-customer only.
- Header + `LWC_VERSION` bumped 1.0.98 → 1.0.99.

Verified with `tmp/test-registered-only-discounts.php` (self-deleting harness,
28 assertions OK, no DB residue): guest rejection through the real
`WC_Discounts::is_coupon_valid()` path, message text, session coupon drop, empty
guest coupon data, My-Account page login gate; customer coupons still valid and
offered; admin/CLI/cron contexts unaffected.

Note: `WC_Coupon::get_code()` returns the code lower-cased (`wc_format_coupon_code()`);
compare coupon codes case-insensitively in tests.
